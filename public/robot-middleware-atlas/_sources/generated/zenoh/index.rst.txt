Eclipse Zenoh
=============

固定源码版本：``9fcd9cb5d364192c3e8a27e66de76f4bc750d1d5``

Zenoh 把发布订阅、查询和分布式数据空间统一在 key expression 之上。Session 是应用入口，Primitives 隔离会话与路由，Face 表示一侧连接关系，resource tree 与 route cache 把表达式匹配结果变成可复用的数据路径，transport pipeline 再完成 batch、frame 和 fragment。

因此它不能只被理解成另一套 topic pub/sub。要读懂一次 put 或 get，必须同时理解 key expression 的集合语义、声明如何改变路由表、消息如何在多个 Face 间改写 WireExpr，以及拥塞控制和可靠性如何沿异步任务与有限通道传播。

阅读源码时从 public entry 出发，沿真实调用链标出对象所有权、线程切换、队列、锁和数据复制，再回到关闭路径检查在途工作如何收束。

统一学习路径
------------

本专题按同一条工程认知链组织。先理解它解决的系统问题，再认识组件边界；随后沿真实源码调用链追踪数据、线程与所有权。读懂实现以后，再分别讨论语言机制、设计取舍、性能边界、可迁移思想和最小复刻。实际项目案例放在这八步之后，用来观察这些机制怎样进入完整机器人系统。

1. **功能介绍与需求分析**：:doc:`建立使用场景、核心保证与适用边界 <foundations>`。
2. **组件地图**：:doc:`先看清公开入口、核心对象和控制流关系 <architecture-map>`。
3. **自顶向下源码实现**：:doc:`从第一条主调用链进入实现 <session-runtime>`，再按下方源码目录顺序阅读后续模块。
4. **C/C++ 或 Rust 机制**：:doc:`把所有权、模板、RAII、ABI 与并发原语映射回设计目的 <rust-cpp-design-lab>`。
5. **优秀设计与工程取舍**：:doc:`回看分层、接口和数据结构为什么这样组织 <design-recap>`。
6. **缺点与性能边界**：仍在 :doc:`设计总结 <design-recap>` 中检查容量、复杂度、尾延迟、故障和不适用条件。
7. **可迁移设计思想**：从 :doc:`设计总结 <design-recap>` 提取能够带到其他运行时、驱动和机器人框架中的方法。
8. **最小复刻**：进入 :doc:`实现练习 <rust-cpp-design-lab>`，按依赖顺序重建最小闭环，并用关闭、过载和竞态不变量判断实现是否完整。
9. **实际开发与知名项目**：从 :doc:`环境与基础操作 <use-environment>` 开始，最后进入 :doc:`真实项目案例 <case-study-rmw-zenoh>`。
